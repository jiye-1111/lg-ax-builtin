# 계정과 저장

## 계정 종류

| 종류 | 가입 | 할 수 있는 것 |
|---|---|---|
| 고객 | 이메일·비밀번호·이름. 바로 사용 | 내 집 목록, 꾸민 집 서버 저장(자동·수동), 저장본으로 되돌리기 |
| 기사 | 이메일·비밀번호·이름 + 서비스센터·사번·연락처. **관리자 승인 후** 사용 | 상담 요청 목록, 방문 스캔 등록(올린 집의 담당 기사가 됨), 맡은 집 저장 |
| 관리자 | 가입 불가. 서버 `.env`의 `ADMIN_EMAIL`·`ADMIN_PASSWORD`로 서버 시작 때 만든다 | 기사 승인·거절·이용 중지·다시 승인 (`#/admin`) |

기사 상태: `pending`(승인 대기) → `approved` / `rejected`, `approved` → `suspended` → `approved`.
정지·거절된 기사는 로그인이 막히고, 이미 받은 토큰도 바로 안 먹힌다.

## 로그인 방식

- 웹(housetwin.pages.dev)과 API(sslip.io)가 다른 사이트라서 쿠키 대신 `Authorization: Bearer <토큰>`을 쓴다. 브라우저가 제3자 쿠키를 막아도 로그인이 풀리지 않는다.
- 토큰은 32바이트 랜덤, 30일. 서버 DB에는 토큰의 SHA-256만 저장한다. 로그아웃하면 바로 지운다.
- 비밀번호는 scrypt(n=2^14, r=8, p=1, 솔트 16바이트)로만 저장한다. API 응답에는 해시가 나가지 않는다.
- 없는 이메일과 틀린 비밀번호는 같은 문구·비슷한 시간으로 답한다(가입 여부가 드러나지 않게).
- 10분 동안 같은 이메일로 5번, 같은 IP에서 20번 틀리면 429로 잠깐 막는다. 강의실처럼 한 공유기를 여럿이 쓰는 경우를 생각해 IP 쪽을 넉넉하게 뒀다.
- 상담 요청 목록(`GET /api/requests`)은 고객 이름·연락처·주소가 있어서 승인된 기사와 관리자만 본다.

## 집 주인

- 로그인한 채로 스캔을 올리면 고객은 `owner_id`, 승인된 기사는 `technician_id`가 된다.
- 로그인 전에 꾸미던 집은 리모델링 화면에서 로그인하면 고객 링크의 토큰(`share_token`)으로 내 계정에 가져온다(`POST /api/projects/{pid}/claim`). 이미 주인이 있는 집은 못 가져온다.

## 저장

집 상태는 원래도 바꿀 때마다 서버 DB에 바로 들어간다. 저장은 그 위에 **되돌아갈 수 있는 저장본**을 남기는 기능이다.

- 자동 저장: 리모델링 화면이 10초마다 버전을 보고, 바뀐 게 있으면 사람마다 한 칸(`{pid}.auto.{user}`)을 덮어쓴다. 다른 화면으로 가거나 창을 숨길 때도 한 번 저장한다.
- 수동 저장: 저장 버튼이나 `Ctrl+S`(맥 `⌘S`). 저장 기록 창에서 이름을 붙여 저장할 수도 있다. 집마다 30개까지.
- 되돌리기: 제품 배치·마감재·스타일·영역·벽 실측값·방위·공유기 자리·동선 표시를 저장본으로 바꾼다. 스캔 원본, 도면 파일, 주인 정보는 그대로 둔다. 되돌리기 전 상태는 자동 저장에 먼저 남긴다.
- 저장·목록·되돌리기는 집 주인, 담당 기사, 관리자만 된다.

## 알고 있는 한계 (시연용)

- 집을 바꾸는 기존 API(제품 놓기, 마감재 등)는 MCP·고객 링크와 같이 쓰려고 로그인 없이 열려 있다. 실서비스로 가면 고객 링크 토큰이나 로그인으로 막아야 한다.
- 토큰을 브라우저 localStorage에 둔다. 화면에 그리는 값은 모두 이스케이프하지만, 실서비스에서는 같은 사이트로 API를 옮기고 HttpOnly 쿠키로 바꾸는 게 맞다.
- 비밀번호 찾기·이메일 인증은 없다.
