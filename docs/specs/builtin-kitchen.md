# 빌트인 주방: 가전 맞춤장 · 주방 모듈 · 마감

LG 가전을 고르면 그 모델이 들어갈 **빈 공간을 가진 장**을 만든다. 닫힌 상자 하나를 카탈로그에 넣는 게 아니라, 측판·위 수납장·뒷판·상판·걸레받이·틈막이판·측면 마감판을 따로 가진 장이다.

흐름: 가전 고르기 → 장 만들기 → 옆 장 잇기 → 색·마감 → 설치 조건 확인.

## 두 가지 방법
| | 새 장 설계 | 기존 장에 넣기 |
|---|---|---|
| 안쪽 치수 | 외경 − 부재 두께 (설계값) | 줄자로 잰 안쪽 실측값 그대로 |
| 가전을 고를 때 | 공식 기준이 있는 모델이면 권장 안쪽 치수로 외경을 맞춘다 (사용자가 다시 고칠 수 있음) | 장 크기를 바꾸지 않는다 |
| 판정 표시 | "설계값" — 현장 실측이 아님 | "실측값". 비운 칸이 있으면 판정 불가 |

## 데이터
- 장 = 꾸미기 배치 `decor:cab_<종류>`. 외경은 `size_m`(m), 나머지는 배치의 `cab`:
  `{kind, mode, outer_mm, measured_mm?, parts{side_l, side_r, back, filler_l, filler_r, end_l, end_r, upper_h|counter, toe_kick, toe_recess, shelves, drawers, doors, kick_across, bowl}, finish{front, body, top, handle}, glass?, base_mm?}`
- 장 안 가전 = 보통 LG 제품 배치 + `in_cab: <장 id>`. 자리는 서버가 장 안쪽 빈 공간에서 계산한다(장을 옮기면 같이 간다). 가전 3D 모델은 늘이거나 줄이지 않는다.
- 판정 결과 = 장 배치의 `cab_check`. 장 안 가전의 `verdict`도 이 값으로 바뀐다(`reasons[0].code = "cabinet"`).
- 안쪽 치수: 폭 = 외경 폭 − (측판 + 틈막이판 + 측면 마감판), 깊이 = 외경 깊이 − 뒷판, 높이 = 냉장고장은 외경 − 위 수납장, 식기세척기 자리는 외경 − 상판.
  판정은 이 안쪽 치수만 본다. 측판 두께를 판정에서 한 번 더 빼지 않는다.
- 장을 지우면 안에 넣은 가전도 같이 빠진다. 복사하면 부재·마감은 그대로, 가전은 따라가지 않는다.
- 목록에서 그냥 놓은 장(되돌리기·MCP)도 그 종류의 기본 부재로 장이 된다.

## 판정 (recommender/cabinet_fit.py)
- 기준은 `data/catalog/install_rules.json`에 **모델별로** 적힌 것만 쓴다. 같은 카테고리 다른 모델 값으로 채우지 않는다.
- 결과: 적합 = 검사 범위의 필수 조건 모두 충족 · 조건부 = 추가 조치 필요 · 불가 = 필수 조건 미충족 · 판정 불가 = 공식 규칙이나 필요한 실측값 없음(외형 비교는 보여 준다).
- 폭·높이·깊이마다 필요 / 확보 / 부족(또는 넘침) mm, 값의 출처(설계값·실측값), 근거 문장.
- 정면: 가전 깊이 − 장 안쪽 깊이 → 장 앞면과 맞음(±1 mm) / 돌출 / 들어감 (mm).
- 식기세척기: 좌우 나사 고정면(측판이나 옆 장이 없으면 불가), 걸레받이 높이(120 mm 이하면 조건부 · 낮은 걸레받이용 모델 확인), 급수·배수·전원은 항상 "현장 확인". 싱크 하부장이 옆에 있어도 배관 확인으로 바꾸지 않는다.
- ‘적합’은 검사한 범위 기준이라는 문장을 같이 보여 준다.

## 3D 문 열림 근사 (apps/web/js/cabinet.js)
- 서버 공식 판정과 따로 계산하고 따로 보여 준다.
- 문짝은 두께 60 mm 판. 옆 경첩 문은 0°→90°를 3°마다, 식기세척기 문은 아래 경첩으로 앞으로 내린다(문 밑 높이 = 걸레받이 기준 150 + 다리 올린 만큼).
- 걸림 대상: 자기 장의 측판·위 수납장·걸레받이, 옆 장의 부재와 손잡이, 아일랜드·가구, 벽, 스캔 가구. 걸리면 처음 걸린 각도의 문짝을 3D에 빨갛게.

## 모듈
- 1단계: 냉장고·김치냉장고장, 식기세척기 자리, 싱크 하부장(볼·수전), 서랍형 하부장, 상부장, 키큰 팬트리장, 유리 상부장, 이어지는 상판, 틈막이판, 측면 마감판.
- 다음 단계(같은 구조, 아직 놓을 수 없음): 인덕션 하부장·후드장, 오븐 키큰장, 코너장, 수납 아일랜드, 유리 키큰장.
- 하부장 정면은 상판 앞 끝에서 20 mm 들어가고, 걸레받이는 들임만큼 더 들어간다.

## 마감 (data/finishes/cabinet_finishes.json)
- 부위: 도어·서랍 앞판 / 몸통·측면 마감판 / 상판 / 손잡이·프레임. 한 장 또는 고른 여러 장에 한 번에.
- 판: 웜화이트(무광·유광), 아이보리, 그레이지, 토프, 차콜(무광·유광), 세이지, 네이비, 라이트오크, 월넛. 상판: 화이트 스톤, 웜베이지 스톤, 다크 세라믹.
- 무광·유광(클리어코트)·나뭇결·돌결이 3D에서 다르게 보인다. 가구 미리보기 색이고, LG 가전 공식 색과 섞지 않는다.
- 유리장: 유리판과 프레임이 따로, 몸통·선반은 불투명. 유리는 투명(기본)·브론즈·스모크·골유리. 유리 문도 문 열림 검사에서는 문이다.
- 한샘·IKEA는 구성·마감 레퍼런스로만 봤다. 치수 값은 가져오지 않았다.

## API
- `GET /api/cabinet/kinds` 종류·마감·공식 기준이 있는 모델
- `POST /api/projects/{pid}/cabinets` `{kind, mode, sku?, center_xz?, yaw_rad, outer_mm?, measured_mm?, parts?, finish?, glass?}`
- `PATCH /api/projects/{pid}/cabinets/{id}` 모드·외경·실측·부재·마감·유리·높이
- `PUT /api/projects/{pid}/cabinets/{id}/appliance` `{sku|null, resize}`
- `POST /api/projects/{pid}/cabinets/finish` `{ids, part, finish}`
