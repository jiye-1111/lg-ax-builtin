### 2026-11-25: 설치 계약(설명서 조건) 연결

- 묶음의 모델별 설치 계약 56개를 `data/lg-library/contracts/<모델명>.json`에 그대로 두었다. 제품 설명서에서 옮긴 설치 조건이고, 규칙마다 설명서 문서 번호와 주소가 적혀 있다.
- 설명서에 수치로 적힌 값만 카탈로그에 넣어 판정에 쓴다 (`uv run python tools/catalog/add_contract_values.py`, 55개).
  - 환기 이격 → `clearance_mm`: 일반 냉장고·와인셀러 양옆·뒤·위 100, 전자레인지·광파오븐 양옆·뒤 100에 위 200
  - 인덕션 상판 타공 560 × 480 → `cutout_mm`
  - 식기세척기 장 개구 최소 600 × 815 × 600 → `required_space_mm`
  - 카탈로그에 이미 있던 값은 건드리지 않았고, 계약에 없는 값은 null 그대로다. 근거는 제품별 `spec_notes`에 적었다.
- 현장 값이 있어야 알 수 있는 조건(개구 최대 폭, 급수 압력, 전원, 지지면 높이, 후드 간격 …)은 설치 전 확인 목록에 "설치 설명서 조건" 한 줄로 나온다. 상태는 늘 현장 확인이다.
- 설명서에 수치가 없는 것(문·서랍이 열리는 경로, 정비 공간, 1인 사용·통행 공간)은 "설명서에 수치가 없어 현장에서 볼 것" 줄로 남긴다. 모델 모양에서 거꾸로 계산해 통과시키지 않는다 (묶음 안내서 6번).
- 묶음의 판정 엔진(installation-engine.mjs)은 쓰지 않았다. 판정은 지금처럼 서버 코드(`docs/specs/fit-rules.md`)가 하고, 계약을 읽는 코드는 `services/recommender/recommender/contract.py`다. 출처가 공식·실측·프로젝트 기준이 아닌 규칙은 읽지 않는다.
